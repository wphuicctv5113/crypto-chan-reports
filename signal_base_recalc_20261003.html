一、先更正一条我上轮报错的数据（重要）

我上轮说「旧 BASE 与实际表现 r = -0.257 负相关、基准分失效」—— 这个结论不成立。

口径澄清（这一步很关键，三种指标测的是三件事）
  • max_gain（MFE）= 从推荐那一刻起，最大能浮盈多少 ⇒ 这就是老板口径「从被推荐那一刻起，后续还能涨多少」，全样本可算

  • 旧 BASE 原注释写的是「72h 前向」⇒ 与 post72h_px 不同源，这正是口径错位的来源

三、必须诚实说明的三点局限

  • 样本量不对等：v1 有 2896 条但类型分布极不均（breakout 878 / accumulate 151 / shrink_stop 73），base_ready 仅 2 条、room_launch 3 条 ⇒ 这两个新类型 无法拍板，只能沿用旧值或继续收集。
  • MFE 是乐观口径：它取「期间最高点」，不含出场时机。真实收益要看已平仓 avgR， 但已平仓样本仅 90 条、且集中在少数类型，不足以支撑按类型重排 BASE。
  • 混杂因素未剥离：MFE 受「入场时该币已涨多少」「市场整体状态」影响， 本次未做分层控制。所以这批数字适合判断排序是否反了，不适合直接当绝对基准值。

四、方案选项（请老板拍板）

方案 A：v1 重排 + v2 保持（推荐）

  • v1 段按 MFE 中位重排 BASE；v2 段一字不改（相关性已正）
  • 做法：BASE 拆成 BASE_V1 / BASE_V2，由 signals.engine 自动选表 （与「星级已按 engine 分段」的既有做法一致）
  • 风险：v1 样本占比 82%，重排会影响绝大多数推荐流，需观察星级倒挂是否真缓解

方案 B：只加监控不重排

  • 把本次重算做成监控项，等 v2 样本补齐再定（样本线 n≥100 再拍板）
  • 风险：v1 继续用反排序的 BASE，星级倒挂短期不会缓解

方案 C：暂不动 BASE，先做单一事实源（阶段1 后半段）

  • 本轮只建 core/signal_types.py 把四张表合一（架构收益），BASE 值原样搬入
  • 风险：负相关问题延后，但架构债先还了
